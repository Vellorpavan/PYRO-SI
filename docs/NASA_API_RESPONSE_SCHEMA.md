## 1. Executive Overview

This document specifies the response schema contracts for the Parse.bot web scraper API endpoint:
```http
GET/POST https://api.parse.bot/scraper/328daab1-12f9-4464-b73d-b5e0c392bfe7/list_data_resources
Header: X-API-Key: [REDACTED_API_KEY]
```

It establishes:
1. The authentic error response schema verified by live server probes.
2. The dynamic data resource collection schema generated by Parse.bot scrapers.
3. The bidirectional mapping contract between raw Parse.bot scraped items and canonical GODEYE // PYRO-SI investigation models (`investigation.schema.json`).
4. Strict sanitization, type validation, and credential leak prevention rules.

## 5. Bidirectional Mapping: Parse.bot Item to Canonical GODEYE Model

To maintain schema harmony across the application, raw Parse.bot items map to the established schema `src/data/schemas/investigation.schema.json`:

```
┌───────────────────────────────────────┬──────────────────────────────────────────┬─────────────────────────────┐
│ Parse.bot Scraper Field               │ GODEYE // PYRO-SI Canonical Field        │ Transformation / Validation │
├───────────────────────────────────────┼──────────────────────────────────────────┼─────────────────────────────┤
│ `id`                                  │ `id` (e.g. `PSI-25`)                     │ Standardize to canonical ID │
│ `psi_id`                              │ `psiId`                                  │ Preserve canonical PSI key  │
│ `title`                               │ `title`                                  │ String, trimmed             │
│ `title` (acronym prefix)              │ `code` (e.g. `BASS-II`, `Saffire-I`)     │ Regex extraction `^([A-Z0-9-]+)`│
│ `facility`                            │ `facility` & `rack`                      │ Facility code mapping       │
│ `fuel_type`                           │ `fuelType`                               │ Enum Solid / Gaseous / etc. │
│ `fuel_details`                        │ `fuelDetails`                            │ String description          │
│ `download_url`                        │ `downloadableAssets`                     │ Validated asset array       │
│ `doi`                                 │ `doi`                                    │ Validated DOI regex         │
│ `url`                                 │ `psiUrl`                                 │ NASA official URL check     │
│ `measurements_available`              │ `verifiedMetadata` / `verifiedDataset`   │ Epistemic classification    │
│ Scraper Source Metadata               │ `provenance`                             │ 7-attribute SPD-41a record  │
└───────────────────────────────────────┴──────────────────────────────────────────┴─────────────────────────────┘
```

## 6. Strict Credential Protection and Sanitization Contract

To prevent accidental exposure or commitment of credentials:
1. **Zero Logging:** Neither the API key nor the `Authorization`/`X-API-Key` request header may ever be written to disk, console, error logs, or validation markdown reports.
2. **Masking:** Any internal debug display must mask keys as `pmx_...[last 4 digits]`.
3. **Recursive Redaction:** The response parser recursively inspects all keys matching `(key|token|secret|password|auth|credential)` and replaces their values with `"[REDACTED]"`.
4. **Environment Isolation:** Keys are strictly injected through `os.environ.get("PARSE_API_KEY")` and never persisted into code repositories or `.env` files committed to Git.
